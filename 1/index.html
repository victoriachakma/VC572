Part 1 - Distance from a point to a curve

Function: y = x² + 5 (plus a second parabola and four non-polynomial functions, used to demonstrate generality). Points for the given parabola: (0,0), (−4,0), (−8,0), (2,0), (6,0).

Finding the closest point on a curve to a fixed point (x₀, y₀) is an optimization problem: minimize the squared distance $$D(x) = (x-x_0)^2 + (f(x)-y_0)^2$$ over every candidate point (x, f(x)) on the curve. The square avoids a difficult square root in the derivative without changing where the minimum sits, since square-rooting is a monotonically increasing operation - whatever x value minimizes D(x) also minimizes the true distance.

Analytical approach

Setting D'(x) = 0 gives the critical-point condition $$D'(x) = 2(x-x_0) + 2(f(x)-y_0)f'(x) = 0$$ Geometrically, this says the vector from the fixed point to the curve must be perpendicular to the curve's tangent line at that point - the shortest path from a point to a curve always meets the curve at a right angle. For most of the points tested here this condition reduces to a cubic in x with no clean closed form, so it is solved numerically by substitution in the handwritten work, then verified against both numerical methods below.

Numerical approaches

Newton-Raphson applies Newton's root-finding method to D'(x) = 0 (not to D(x) directly - Newton's method finds roots, and the root of D'(x) is the critical point of D(x)): $$x_{n+1} = x_n - \frac{D'(x_n)}{D''(x_n)}$$ When the exact derivative f'(x) is available (the two parabolas here), it is passed in directly; for the non-polynomial cases (exponential, log, rational, radical) the code falls back to a central-difference numerical derivative, $f'(x) \approx \frac{f(x+h)-f(x-h)}{2h}$, since those weren't required to be differentiated by hand.

Golden Section Search needs no derivatives. It reduces a bracket [a, b] by comparing the squared distance at two interior points placed using the golden-ratio split (resphi ≈ 0.381966), discarding whichever side of the interval can't contain the minimum. This split ratio is specifically what lets the algorithm reuse one interior point from the previous iteration instead of recomputing both from scratch each round - that reuse is the entire reason the golden ratio is used instead of, say, plain bisection.

Method 1 - Newton-Raphson (uses the exact derivative when supplied, otherwise falls back to a numerical one):

def newton_raphson(px, py, f, x0, df=None, ddf=None,
                    tolerance=1e-10, max_iterations=100):
    fprime = df if df is not None else (lambda x: numerical_derivative(f, x))
    fdprime = ddf if ddf is not None else (lambda x: numerical_second_derivative(f, x))

    x = x0
    history = [x]
    for i in range(max_iterations):
        g_prime = 2 * (x - px) + 2 * (f(x) - py) * fprime(x)
        g_double_prime = 2 + 2 * fprime(x)**2 + 2 * (f(x) - py) * fdprime(x)

        if abs(g_double_prime) < 1e-14:
            break

        x_new = x - g_prime / g_double_prime
        history.append(x_new)

        if abs(x_new - x) < tolerance:
            x = x_new
            break

        x = x_new

    return x, distance(x, px, py, f), history

Method 2 - Golden Section Search (no derivatives, shrinks a bracket using the golden ratio):

def golden_section_search(px, py, f, a, b,
                           tolerance=1e-10,
                           max_iterations=1000):

    g = lambda x: squared_distance(x, px, py, f)

    golden_ratio = (np.sqrt(5) - 1) / 2  # == 1 - 1/phi == 2 - phi

    c = b - golden_ratio * (b - a)
    d = a + golden_ratio * (b - a)

    history = [c, d]
    iterations = 0

    for i in range(max_iterations):
        iterations += 1

        if g(c) < g(d):
            b = d
            d = c
            c = b - golden_ratio * (b - a)
        else:
            a = c
            c = d
            d = a + golden_ratio * (b - a)

        history.extend([c, d])

        if abs(b - a) < tolerance:
            break

    x_min = (a + b) / 2

    return x_min, distance(x_min, px, py, f), history, iterations

Part 2 - Fitting a line and a parabola

Points: (0, 0.5), (1, 1.5), (2, 3.5), (3, 7.5). Fitting y = mx + b and y = ax² + bx + c by minimizing mean squared error.

Setup - the MSE objective

$$\text{MSE} = \frac{1}{n}\sum_{i=1}^n (y_i - \hat{y}_i)^2$$ Substituting the data directly: $$\text{MSE}(m,b) = \tfrac14\left[(0.5-b)^2+(3.5-(2m+b))^2+(1.5-(m+b))^2+(7.5-(3m+b))^2\right]$$ $$\text{MSE}(a,b,c) = \tfrac14\left[(0.5-c)^2+(3.5-(4a+2b+c))^2+(1.5-(a+b+c))^2+(7.5-(9a+3b+c))^2\right]$$ All three solution methods below (analytical, alternating Newton-Raphson, and true multivariate Newton-Raphson) use the same precomputed power sums, since they all fall directly out of differentiating this same objective: Σx=6, Σy=13, Σx²=14, Σxy=31, Σx³=36, Σx⁴=98, Σx²y=83, n=4.

Analytical solution

Setting every partial derivative to zero gives the normal equations, solved directly as a linear system using the sums above. This gives the exact least-squares answer with no iteration: m = 2.3, b = −0.2 for the line, and a = 0.75, b = 0.05, c = 0.55 for the parabola.

Numerical solution 1 - alternating Newton-Raphson

This method fixes all but one parameter, solves exactly for the remaining one, then cycles to the next parameter and repeats. Each individual step is exact given the other parameter(s) are held fixed, but because the parameters are coupled in the full objective, several cycles are needed before the whole system settles - the line (2 parameters) converges in well under 15 iterations, while the parabola (3 parameters) needs closer to 25, since there is more coupling between three parameters than two.

Numerical solution 2 - true multivariate Newton-Raphson

This is the method the assignment specifies: rather than updating one parameter at a time, all parameters are updated together using the full gradient vector and the full Hessian matrix of second partial derivatives (including the cross terms, e.g. ∂²MSE/∂m∂b): $$\theta_{n+1} = \theta_n - H^{-1}\nabla\text{MSE}(\theta_n)$$ As MSE is a quadratic function of the parameters for both fits here, the Hessian is constant (it doesn't depend on θ at all) - which means this method converges in exactly one step from any starting point, landing on exactly the same answer as the analytical solve. This isn't a coincidence: solving $H\theta_1 = -\nabla\text{MSE}(\theta_0)$ is algebraically the same linear system as the normal equations, so for a quadratic objective, Newton's method and the closed-form least-squares solve are the same computation performed in two different ways.

Alternating Newton-Raphson (one parameter at a time, parabola case shown):

def parabola_newton_alternating(x, y, a0=0.0, b0=0.0, c0=0.0, iterations=25):
    s = power_sums(x, y)
    n = s["n"]
    Sx, Sxx, Sxxx, Sxxxx = s["Sx"], s["Sxx"], s["Sxxx"], s["Sxxxx"]
    Sy, Sxy, Sxxy = s["Sy"], s["Sxy"], s["Sxxy"]

    a, b, c = a0, b0, c0
    history = [(a, b, c, mse_parabola(a, b, c, x, y))]

    for _ in range(iterations):
        a = (Sxxy - b * Sxxx - c * Sxx) / Sxxxx
        b = (Sxy - a * Sxxx - c * Sx) / Sxx
        c = (Sy - a * Sxx - b * Sx) / n
        history.append((a, b, c, mse_parabola(a, b, c, x, y)))

    return a, b, c, history

True multivariate Newton-Raphson (gradient + Hessian together, parabola case shown):

def parabola_gradient_hessian(a, b, c, x, y):
    s = power_sums(x, y)
    n = s["n"]
    Sx, Sxx, Sxxx, Sxxxx = s["Sx"], s["Sxx"], s["Sxxx"], s["Sxxxx"]
    Sy, Sxy, Sxxy = s["Sy"], s["Sxy"], s["Sxxy"]

    grad = np.array([
        -(2 / n) * (Sxxy - a * Sxxxx - b * Sxxx - c * Sxx),
        -(2 / n) * (Sxy - a * Sxxx - b * Sxx - c * Sx),
        -(2 / n) * (Sy - a * Sxx - b * Sx - c * n),
    ])
    H = (2 / n) * np.array([
        [Sxxxx, Sxxx, Sxx],
        [Sxxx,  Sxx,  Sx],
        [Sxx,   Sx,   n],
    ])
    return grad, H


def parabola_newton_multivariate(x, y, a0=0.0, b0=0.0, c0=0.0,
                                  iterations=10, tolerance=1e-12):
    theta = np.array([a0, b0, c0], dtype=float)
    history = [(theta[0], theta[1], theta[2],
                mse_parabola(theta[0], theta[1], theta[2], x, y))]

    for _ in range(iterations):
        grad, H = parabola_gradient_hessian(theta[0], theta[1], theta[2], x, y)
        step = np.linalg.solve(H, grad)
        theta_new = theta - step
        history.append((theta_new[0], theta_new[1], theta_new[2],
                         mse_parabola(theta_new[0], theta_new[1], theta_new[2], x, y)))
        if np.linalg.norm(theta_new - theta) < tolerance:
            theta = theta_new
            break
        theta = theta_new

    return theta[0], theta[1], theta[2], history
